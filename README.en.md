# DMR vocoder (AMBE+2 compatible)

[中文](README.md) · Used by [OpenDMR](https://github.com/va3bpf/OpenDMR), open firmware for the Baofeng DM-32UV (this repository
is its submodule).

An encoder and decoder for the AMBE+2 half-rate vocoder used by DMR (3600x2450: one frame every 20 ms, 49 parameter
bits + 23 error-correction bits = 72 bits). It is our own implementation and interoperates with DVSI's vocoder.
The same algorithm exists in three implementations:

| Implementation | Where | Use |
|---|---|---|
| Python | `py/ambe_encoder.py`, `py/ambe_analysis.py`, `py/ambe_decoder.py` | Reference for research and tuning; every parameter is a module constant |
| C, double | `c/ref/` | Bit-exact with the Python; used to check the errors of the fixed-point version |
| C, fixed point | `c/ambe/` | For embedded use, runs without an FPU: integers and tables, only a few floats per frame |

**Status**: the fixed-point C version transmits and receives on a DM-32 radio (CK803S, 168 MHz) and works over the
air with commercial DMR radios. Per frame, decoding takes 2.40 ms and encoding 13.1 ms; it uses 53.4 KB of RAM.
The radio's output is bit-exact with `bin/ambe_cli.exe` on the PC. PESQ on six Chinese sentences (zh6), decoded
by DVSI's decoder: our encoder 3.13, DVSI's own encoder 2.97.

- Algorithm: `docs/algorithm.md` (in Chinese)
- Research log, what was tried, and the numbers: `docs/notes.md` (in Chinese)

## Setup

The PC-only tests need steps 1 to 4, the md380 tests also need step 5. For the radio tests see part 2 below.

1. **Python 3** and packages: `pip install -r requirements.txt` (numpy, scipy, matplotlib, pystoi; pyserial for the
   radio tests).
2. **Reference sources**: `sh fetch_refs.sh` → `ref/`. `c/build.sh` needs the PESQ code from there;
   `py/gen_tables.py` needs mbelib.
3. **DVSI test vectors**: DVSI's public AMBE-3000 test package <https://www.dvsinc.com/get-hdk_3000/hdkiso/tv.zip>
   (about 520 MB, page <https://www.dvsinc.com/dlapps/appsoft.shtml>). Unpack `dam.pcm`, `clean.pcm`, `noisy.pcm`
   from its root and the `r33/` directory into `data/dvsi/`. Rate r33 is the 3600x2450 that DMR uses:
   - `dam.pcm` etc.: the original input, 8 kHz 16-bit little endian;
   - `r33/<name>.bit`: DVSI's encoder output, 9 bytes per frame; `r33/<name>.pcm`: DVSI's decode of those bits,
     the reference answer for a decoder;
   - `_e1` / `_e2` / `_e5` / `_e10_hd`: hard-decision bits with 1 to 10 % bit errors, `_sd` soft decision,
     `_dtx` with silence suppression.
4. **The C programs for the PC**: `sh c/build.sh` → `bin/pesq_nb.exe`, `bin/vocoder_c.dll`, `bin/ambe_cli.exe`,
   `bin/ambe_ref.exe`. It uses the gcc (MinGW-w64) in PATH; the script first puts `../toolchain/winlibs/mingw64/bin`
   at the front of PATH, so that one is used if it is there.
5. **md380-emu** (optional; a second DVSI reference, much faster than the radio): the DVSI vocoder of the MD-380
   firmware, run under qemu. In WSL (Ubuntu 22.04): `wsl -u root -- bash /mnt/<repo path>/tools/build_md380emu.sh`;
   the apt packages it needs are listed at the top of the script. It is bit-exact with the DM-32's stock codec, so it
   can stand in for the radio in every comparison with "stock".

The test speech zh6 (`out/zh6_input.wav`: THCHS-30 sentences D4, D6, D7, D8, D11 and D12, band-passed to
300 to 3400 Hz, level RMS 3000, 58 s) is made by `python py/zh6_input.py`. The scripts that use it make it
when it is missing.

## Tests

Run every script from `py/` (`cd py`); output goes to `out/`.

### 1. PC only

| Command | What it tests | Needs (see Setup) |
|---|---|---|
| `python ambe_frame.py` | Frame layer self-test: 72 bit ↔ 49 bit round trip, Golay correction, re-encoding the DVSI vectors | 3 |
| `python ambe_encoder.py` | Quantizer round trip: parameters decoded from DVSI's bits and quantized again must come out identical | 3 |
| `python ambe_tone.py` | Tone frames: parsing and regenerating the 1031 Hz frame published by NXDN | — |
| `python tone_test.py` | The decoder's tones: frequency, level, SINAD and THD of the 1031 Hz test tone, a tone sweep and DTMF; plot `out/tone_test.png` | — |
| `python evaluate.py [name ...]` | Log spectral distance (LSD) of our decode against DVSI's, grouped by voiced / mixed / unvoiced frames (default dam clean noisy) | 3 |
| `python compare.py [name]` | Decodes one DVSI vector and plots the input, DVSI, the plain mbelib port and ours: waveforms, spectrograms, spectra; writes the WAVs | 3 |
| `python decode.py x.bit ...` | Decodes any `.bit` file (for example one recorded over the air): WAVs and plots (pitch, voicing, Golay corrections per frame) | — |
| `python encoder_test.py [name ...]` | Our encoder against DVSI's: parameters frame by frame, end-to-end LSD, PESQ / STOI against the original input | 3, 4 |
| `python md380_eval.py [module.CONSTANT=value ...]` | **The main tuning tool**: our encoder through md380's decoder and md380's bits through our decoder, PESQ / STOI against the original; any module constant can be overridden for the run | 4, 5 |
| `python c_eval.py [enc] [dec]` | The fixed-point C against the Python: encoder agreement field by field, decoder PESQ (C fixed point / C double / Python) | 4, 5 |

The first run of `md380_eval.py` encodes and decodes with md380 and caches the results in
`out/md380_eval_ref.json` and `out/md380_<name>.json`. `c_eval.py dec` reads those caches, so run `md380_eval.py`
once first. Examples:

```
python md380_eval.py                                     # the current defaults
python md380_eval.py ambe_analysis.VOICED_ERR=0.5        # try one setting, see the PESQ change against md380
```

### 2. With the radio (DM-32, programming cable)

The DM-32 serves as "a device holding the stock DVSI codec and our fixed-point C": the scripts write its memory and
call functions through the debug commands over the programming cable. Conditions:

- The radio runs the OpenDMR firmware, and this repository is OpenDMR's submodule: the scripts take the function
  addresses from `../src/build/opendmr.elf` (**the ELF must come from the same build as the firmware in the
  radio**) and use `csky-elfabiv2-nm` from `../toolchain/`.
- The radio is on, idle on an **FM channel**, not in hotspot mode, cable on COM6 (each script has `--port`). On a
  DMR channel the radio's own audio uses the vocoder at the same time, and the results are wrong.
- pyserial.

| Command | What it tests |
|---|---|
| `python vocoder_bench.py exact [frames]` | **The fixed-point C on the radio is bit-exact with the PC**: encoder and decoder compared frame by frame (default 200 frames of zh6 from frame 100); exit code 0 when all match |
| `python vocoder_bench.py time` | Milliseconds per frame on the radio for decoding and encoding, the encoder's steps, cycles of software float and integer operations |

Normal `time` results: decoding about 2.4 ms per frame, encoding about 13 ms per frame (the real-time limit is 20 ms).

### 3. Over the air (two radios)

The DM-32 in hotspot mode (OpenDMR firmware); the PC uses it as an MMDVM modem over the programming cable:

| Command | What it does |
|---|---|
| `python hotspot_capture.py [name] [--freq 433450000] [--cc 1]` | Records voice sent by another DMR radio, one `data/capture/<name>_<n>.bit` per transmission; decode them with `decode.py` |
| `python hotspot_tx.py a.wav ... [--tg 9] [--src 4600001]` | Encodes the WAVs with our encoder (or sends a `.bit` as it is) as a group call through the hotspot, to be heard on another radio; `--save x.bit` also keeps the bits |

The frequency and colour code must match the other radio. PESQ misses problems such as a robotic voice, so a change
to the encoder is judged by listening over the air in the end.

## Workflows

- **Tuning the Python encoder / decoder**: `md380_eval.py module.CONSTANT=value` and watch the PESQ change against
  md380, then listen to a good one over the air with `hotspot_tx.py`.
- **After changing the fixed-point C**: `sh c/build.sh`, `python c_eval.py` (agreement with the Python and PESQ must
  not get worse); then build and flash the radio's firmware, `python vocoder_bench.py exact` (everything must match)
  and `time` (no more than 20 ms).
- **After changing the Python algorithm**: change the double C version `c/ref/` until it is bit-exact again, then the
  fixed-point version.
- **Tables**: `python gen_tables.py` (mbelib headers → `py/mbe_tables.py`), `python gen_c_tables.py`
  (→ `c/ambe/ambe_tables.c`).

## File formats

| Extension | Contents |
|---|---|
| `.pcm` / `.raw` | 8 kHz, 16-bit, little endian, mono, no header |
| `.wav` | The same with a WAV header; the scripts resample other rates to 8 kHz |
| `.bit` | 9 bytes = 72 channel bits per frame (DMR interleaved order, most significant bit first in a byte), the same as DVSI's `.bit` |
| `.amb` | The DSD / md380-emu format: header `.amb`, 8 bytes per frame (a status byte + 49 bits, most significant first) |

A DMR voice burst carries 3 frames = 27 bytes (MMDVM uses the same format). The frame layer is described in
`docs/algorithm.md` section 1.
