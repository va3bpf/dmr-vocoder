# 声码器研究笔记（2026-11-05 夜 ～ 11-06）

这份笔记记录 `vocoder/` 研究的思路、做过的实验、结论和下一步。代码说明和早期结果见 `vocoder/README.md`。
算法的最终做法见 `algorithm.md`；第 8 节是定点 C 版进固件的过程（2026-11-06）。

## 0. 从帧层到上机：各步骤的记录（原 README 的“计划”）

编号是当时的计划步骤；数字是当时的结果，后来的改进见后面各节和 `algorithm.md`。

### DMR 语音帧格式（已在 `py/ambe_frame.py` 实现并自测）

- 一个语音突发 = 3 帧 × 72 bit = 27 字节（固件里的 `AMBE_AUDIO_LENGTH`，热点和 MMDVM 也是这个格式），按字节 MSB 先。
- 每帧 72 bit 交织成 4 个码字：C0 24 bit（Golay(24,12)）、C1 23 bit（Golay(23,12)，再异或一串由 C0 的 12 位数据生成的伪随机序列）、C2 11 bit、C3 14 bit，没有保护。
- 解出 12 + 12 + 11 + 14 = 49 bit 声码器参数，每 20 ms 一帧。
- C0 第 24 位是整体**偶校验**（mbelib 不检查，用 DVSI 测试向量确认）。
- DVSI 的 r33 `clean`、`dam`、`noisy` 共 8563 帧：Golay 纠错数全为 0，重新编码逐位一致。
- NXDN TS 1-A 7.2.1 公开的两个向量（NXDN 用同样的 AMBE+2 2450）也逐位吻合：静音帧
  `B9E881526173002A6B`（= MMDVMHost 的 `DMR_SILENCE_DATA`，b0 = 124）和 1031.25 Hz 单音帧 `CEA8FE83ACC458200A`。
- 未解决：`_dtx` 向量里部分帧的 C1 纠错数不为 0，静音帧的格式还没研究。
- **b3 / b4 的 4 个比特位置**：mbelib、DSD、OP25 照标准草案（TIA-102.BABA-1 Table 8）把 b3 最低位放在第 40 位、
  b4 低 3 位放在 41～43；DVSI 的声码器是 b4 低 3 位在 40～42、b3 最低位在 43（go-ambe2 用电台的 DVSI 声码器
  黑盒测出）。用 DVSI 的位置，我们对 DVSI 解码的 LSD 降 0.2～0.35 dB（dam 6.97、clean 7.28、noisy 7.30），
  编码器端到端 8.50 → 8.34。量化往返测试查不出这个错，因为两边用同一张表。
- DVSI 编码器 32 个 b1 码字都用（包括表里重复的 1、3、13、15 和全清的 17～31）；把从 DVSI 解码输出测得的
  清浊音换进表里 LSD 反而变差，所以解码保持 mbelib 的表。我们的量化器遇到等价码字取编号最小的，不会用到它们。

### 单音帧

前 6 bit 全为 1 的帧是单音帧（TIA-102.BABA-1）：8 bit 单音编号重复 4 次，7 bit 对数幅度（127 = 满幅，
每级 0.711 dB）。编号 5～122 是 31.25 × 编号 Hz 的单音，128～163 是 DTMF、KNOX、呼叫进程双音，255 是静音。
1031 Hz 测试音的 b0 = 122，mbelib 当成擦除帧输出静音；我们的解码器按连续相位合成（`py/ambe_tone.py`）。

`py/tone_test.py`：频率、电平、SINAD 都接近理想，但这只说明帧格式和合成正确（解码端本来就是按参数合成纯正弦）。
幅度换算（127 = 32767 峰值）是按标准理解的，还没和 DVSI 解码的实际电平核对。
有意义的下一步：另一台电台的话筒对着 1 kHz 单音发射，热点录下后用我们的解码器测，这样测的是语音通道；
反过来让 DM-32 发 1031 Hz 单音帧，用商用电台收听、录音，核对电平。

### 计划

1. 帧层：72 bit ↔ 49 bit。**完成**（随机数据往返 + 纠错自测 + DVSI 向量逐位一致）。
2. 用真实数据验证：**用 DVSI 测试向量完成**。以后再用电台热点模式抓原厂 blob 的帧复核。
3. 解码器：49 bit → 参数（基频、清浊音、频谱幅度）→ 合成 8 kHz PCM，输出 WAV 试听。先照 mbelib 做，再改进音质。
   **mbelib 移植完成**（原样保存在 `py/ambe_decoder_mbelib.py`），**并已向 DVSI 调整**（`py/ambe_decoder.py`，
   每项改动都是 `Decoder` 的选项，默认值就是最接近 DVSI 的设置）。`py/evaluate.py` 给出数字：
   每帧 256 点频谱，按频谱距离对齐延时，算对数谱距离 LSD 和分频段的平均偏差，按浊音 / 混合 / 清音 / 停顿分组。

   | 改动 | dam 的 LSD |
   |---|---|
   | mbelib 原样 | 17.1 dB（clean 17.9，noisy 20.3） |
   | 输出增益 7 → 2（mbelib 高约 12 dB 并削波） | 10.4 |
   | 去掉 mbelib 在 2700 Hz 以上清音谐波上加的 `rand()`：均值不为零，加窗后成了低频“噗噗”声和宽带噪声 | 9.0 |
   | 清音改成频域整形的白噪声，只在清音频带 (l±0.5)·w0 内，每个频带功率 = 幅度 Ml 的正弦。清音增益在自然值 1.0 时最好 | 8.4 |
   | 频谱增强减半（mbelib 的增强让 2 kHz 以上偏弱，关掉又偏强） | 8.2 |
   | 输出 4 阶 120 Hz 高通（DVSI 低频压得很低） | 8.0 |
   | 评估改按频谱距离对齐延时（包络相关差了约 60 样点） | 7.3 |
   | 低次谐波相位连续插值（IMBE 式 134～138，mbelib 注释掉了） | **7.2**（clean 7.5，noisy 7.7） |

   能量：每帧与 DVSI 平均相差 0.9～1.5 dB，整体电平一致。

   下限：两个随机种子互比，浊音 0.6 dB、混合 5.5 dB、清音 7.3 dB。清音已接近下限；浊音帧 LSD 约 6.4，
   谐波峰的位置和高度与 DVSI 重合（基频相差 < 1% 的帧占 97%），剩下的差别主要在谐波之间的谷底（取决于相位）。

   真实信号：用 `hotspot_capture.py` 录到另一台 DMR 电台讲的中文（433.450 MHz、色码 1），`decode.py` 解码能听清；
   51 帧有 1～2 位 Golay 纠错，没有重复帧。

   还没做：3.7 kHz 以上浊音偏弱约 4 dB（我们只合成到 L·w0）；停顿段偏低 2～4 dB；
   波形比 DVSI 更像脉冲（低次谐波相位一致），峰值偶尔超过 30000，DVSI 最大 25074；误码帧、音调帧、DTX 静音帧的处理。
4. 编码器：PCM → 参数 → 49 bit。**进行中**。自己写（OP25 是 GPL，只作理解算法的参考），码表用 mbelib 的。
   - 量化：解码器反过来，带一份解码器状态镜像保证预测一致。DVSI 比特解出参数再量化：解出的参数与 DVSI 完全相同
     （比特不同的帧是等价码字：V/UV 码本有重复行，块长 < 6 时 HOC 只用前几个分量）。
   - 分析：320 点归一化自相关粗估周期，频域谐波拟合细化 w0（0.03 %），选出后检查 2、3 倍 w0 防半频；
     每个谐波在 (l±0.5)·w0 内最小二乘拟合，清浊音按 500 Hz 频带（码本的分辨率）比较拟合残差；
     浊音幅度取拟合正弦，清音取同功率正弦，再除以解码器增益 2。
   - 对齐：DVSI 第 k 帧的中心在输入的 160k − 200 处（DVSI 增益和输入能量互相关）；基频在 −280 处与 DVSI 的
     索引最一致，但端到端不更好，所以都用 −200。
   - `dam` 上与 DVSI 对照：基频 97.8 % 在 5 % 以内，倍频 / 半频 0.4 %；清浊音一致 75.7 %；增益 −0.7 dB
     （逐帧 2.5 dB）；谱包络形状 3.3 dB；端到端 LSD 8.5 dB（第一版 9.2）。
   - 神谕实验（只把某项换成 DVSI 的）：基频 → 7.1，清浊音 → 8.1，谱幅度 → 7.8，基频 + 清浊音 → 4.6
     （随机噪声的下限约 3.6）。基频只有约 45 % 与 DVSI 同一量化级，其余在 ±1 级跳动：
     下一步是跨帧基频跟踪，然后清浊音。
   - 改进（参考 go-ambe2 和 TIA-102.BABA 的思路，自己实现）：E(P) 跨帧基频跟踪（向前看两帧、向后看两帧、约数检查），
     clean / noisy 的倍频错误 3.7 % → 1.0 %、5.3 % → 3.6 %；在量化后的 w0 和它的 L 上拟合谐波；
     PRBA / HOC 按幅度加权的重建误差联合搜索（重建是线性的，与解码器逐位一致）。按量化后清浊音取幅度没有改善，关着。
   - 评估改为对原始输入（同一个解码器）：LSD 对 DVSI 输出会把任何基频差别都算成错。
     PESQ（我们的解码器）：dam 3.30 / DVSI 编码 3.19，clean 3.16 / 2.93，noisy 3.15 / 2.59（noisy 对 DVSI 不公平：
     它压低背景噪声，我们照编）。我们的解码器解 DVSI 比特 3.19，DVSI 自己解 3.36。
   - **空中互通**：`hotspot_tx.py` 发我们编的中文，商用 DMR 电台能收听。
   - **与原厂编码器对比**（`stock_compare.py`，THCHS-30 六句中文 58 秒）（2026-11-07 起固件不再包含、也不再支持原厂编解码器，`stock_codec.py` / `stock_compare.py` / `stock_eval.py` 已删除；下面是当时的结果）：

     | 编码器 | 解码器 | PESQ | STOI |
     |---|---|---|---|
     | 我们 | 原厂 | **3.126** | 0.847 |
     | 我们 | 我们 | 3.086 | 0.847 |
     | 原厂 | 原厂 | 2.965 | 0.840 |
     | 原厂 | 我们 | 2.639 | 0.808 |

     原厂编码器在 dam 上的参数与 DVSI 测试向量很接近（基频多在 1～2 % 内），但比特不同。
   - **静音帧**：空中听我们的版本，字与字之间有怪声（本地解码没有）。原因：停顿处我们发低电平的浊音帧
     （低频带判浊 95 %），原厂发静音帧（b0 = 124、b1 = 16、低增益，PRBA / HOC 照常量化成舒适噪声；
     go-ambe2 测得 DVSI 播静音帧时约衰减 13 dB）。加了 VAD（跟踪底噪和语音峰值，低于峰值 45 dB 为静音，
     拖尾 1 帧）和静音帧，与原厂的静音判决逐帧一致 88 %；空中再听“好多了”。
   - 还没做：低电平语音帧仍几乎都判浊（原厂在峰值下 35～45 dB 的帧只有一半判浊）；我们的解码器解原厂比特比原厂
     解码器低 0.33（静音帧衰减、相位分散、全部谐波相位插值）；用新编码器重跑四种组合。
5. 定点 C，上机。**完成**（2026-11-06）。
   - `c/ambe/` 是整数版（CK803S 没有 FPU，软浮点乘法约 270 个周期）；`c/ref/` 是双精度参考版，与 Python 逐位一致。
     电台上的编码、解码和电脑上的 `ambe_cli` 逐位一致（直接调用 `vocoderEncodeFrame` / `vocoderDecodeFrame` 比较，见下）。
   - 时间都去哪了（在电台上实测，`vocoder_bench.py time`）：表放在 Flash 时每次随机查表都要经缓存，很慢；
     常用的 24 张表放进 RAM 后解码 4.85 → 2.13 ms，编码 15.4 → 12.8 ms。代码则相反：RAM 只有一个端口，
     小循环放在有缓存的 Flash 里更快，所以解码器代码留在 Flash；编码器代码放 RAM，因为放 Flash 时
     Flash 总线的活动串进了话筒，发射的声音变差。
   - 再压 RAM：余弦表和 FFT 旋转因子只存四分之一周期（值不变）、窗变换表 32 点一个频点、PRBA24 乘积改为现算：
     71.9 → 53.4 KB，每帧多约 0.3 ms。编码器用 -Os 能再省 2.6 KB，但每帧 16 ms，没用。
   - 编码器按每个频点 23 个谐波、每帧约 52 次谐波拟合（基音细化）；再快就要改算法（比如先粗判 1/2、1/3 倍周期再细化）。
6. 固件：只用我们的（`src/dmr/vocoder.c`），第一次 DMR 编解码时从 Flash 拷入 0x44400 开始的 RAM（`ckcpu.ld` 的
   `.vocoder_overlay`）。当初原厂 blob 也在、两者轮流用这块 RAM 切换对比；2026-11-07 起原厂编解码器从固件里去掉了。
7. 真实话筒（2026-11-06，从电台录话筒采样定位）：
   - DM-32 的话筒采样带约 2470 的直流：编码器输入加了整数去直流（`dc_block()`，约 10 Hz，从第一个采样起算），三份实现一致。
     没有它时基音跟踪被打偏到 P≈20，整段全判清音（“嗓子哑了”）。
   - 打开采集后 ADC 用 150 ms 从约 12000 落到直流；每次发射时切话筒开关还有一个到 −32000 的冲击。
     这两件事在固件里解决（话筒按模式接、丢掉帧头期间的采集时重置编码器），见 OpenDMR 的 `docs/architecture.md` 第 7 节。
   - 测试语音上编码器和原厂在各频段的能量差在 ±1 dB 内；最高频段（3.5～4 kHz）判浊的比例我们只有约 18 %，原厂约 64 %，
     空中听高频略不如原厂（试过放宽高频段门限，没有采用）。

## 1. 目标和评估方法

目标：自己写一个与 DMR 兼容的 AMBE+2（3600x2450）编码器和解码器，替换固件里的原厂闭源编解码器。

**评估方法的演变**（这是本轮最重要的收获之一）：

| 阶段 | 方法 | 问题 |
|---|---|---|
| 1 | 跟 DVSI 测试向量的解码输出比 LSD | 基频跟 DVSI 差一级就算错，哪怕我们更接近原声 |
| 2 | 跟原始输入比 LSD / STOI / PESQ，用我们自己的解码器 | 我们的解码器跟商用电台不同，空中试听与分数不符 |
| 3 | 我们编码 → **电台里的原厂解码器** → 跟原始输入比 PESQ | 准，但每个配置 3～4 分钟，要电台退出热点模式 |
| 4 | 我们编码 → **md380-emu（MD-380 固件里的 DVSI 声码器）** → PESQ | 跟电台原厂完全一致，2.5 分钟测三份材料 |

md380-emu 与电台原厂编解码器的一致性：

| | md380-emu | 电台原厂 |
|---|---|---|
| zh6 编码加解码 PESQ | 2.967 | 2.967 |
| dam 编码加解码 PESQ | 3.534 | 3.534 |
| 电台原厂编的 zh6 比特，md380 解码 | 2.965 | 2.967（电台自己解） |
| DVSI 测试向量 dam 的比特，md380 解码 | 3.374 | 3.363（DVSI 自己解） |

结论：**md380-emu 可以代替电台做评估**，电台只用于最后的空中试听。

工具：
- `py/md380emu.py` + `tools/build_md380emu.sh`、`tools/md380emu.sh`：在 WSL 里用 qemu 运行 md380-emu
  （md380tools 的工具，对本地副本做了三处修正：编码不丢前 26 帧、`.amb` 文件头判断、跳过递归编译）。
- `py/md380_eval.py`：编码器（我们编 → md380 解）和解码器（md380 编 → 我们解）对 md380 自己编解码的 PESQ 差，
  加上基频帧间跳变统计。
- 当时还有 `py/stock_codec.py`、`py/stock_eval.py`：用电台原厂编解码器做同样的事（已删除，见上）。
- `py/hotspot_tx.py`：经 DM-32 热点把比特发到空中，商用电台收听。

材料：`zh6` = THCHS-30 六个说话人同一句中文（58 秒，300～3400 Hz 带通、电平调到 RMS 3000）；
DVSI 测试向量 `dam`、`clean`（英文？内容未核实）。

## 3. 解码器：用 md380 黑盒探测 DVSI 的做法

方法：把同一个参数帧重复 30 次送进 md380 解码器（预测稳定后），在输出上按 l·w0 最小二乘拟合正弦，
得到每个谐波的实际幅度，与解量化的 Ml 比较。

发现：
1. **频谱增强**：md380 对每个谐波的增益 = 0.95 × mbelib 增强公式的增益 + 0.66 dB（相关系数 0.83，
   残差中位数 ±0.5 dB 以内）。即 **DVSI 用的就是 mbelib 那个增强公式，全强度**。我们之前按 LSD 选了半强度，是错的。
2. 只对浊音谐波增强：更差。DVSI 对所有谐波都增强。
3. **静音帧**：md380 / 电台原厂播放时约衰减 11 dB（go-ambe2 测得 0.228）。我们取 0.25。
4. **相位分散**：每个谐波固定的伪随机相位偏移（go-ambe2 的发现），dam 3.185 → 3.240。
5. 电平：总增益 2.35、清音增益 0.77 时，浊音 / 混合 / 清音三类帧都与 md380 相差 0.2 dB 以内。

解码器（md380 编码 → 我们解码）PESQ：

| | 本轮开始 | 现在 | md380 自己解 |
|---|---|---|---|
| zh6 | 2.786 | 2.799 | 2.967 |
| dam | 3.274 | 3.288 | 3.534 |

剩余差距约 0.17～0.25，不在电平上（电平已对齐，PESQ 几乎不变），在合成细节上。go-ambe2 也卡在这里（他们差 0.16，
“原因不明”）。探测还看到清音帧 md380 在 2.5～4 kHz 比我们亮 3.5 dB，原因待查。

## 4. 编码器

当前做法（都是自己按 TIA-102.BABA 的思路和 go-ambe2 的发现实现，不用别人的代码）：
- 基频：E(P) 跨帧跟踪（向前看两帧、向后看两帧、约数检查）+ 转移代价 1.0 + 频域谐波拟合细化（0.03 %）+ 防半频。
- 在量化后的 w0 和它的 L 上拟合谐波；清浊音按 500 Hz 频带（码本的分辨率），随电平变化的阈值，带迟滞。
- 加权量化（PRBA / HOC 按幅度加权的重建误差，b3/b4 联合搜索）。
- VAD + 静音帧（b0 124、b1 16、频带功率作为舒适噪声），静音帧不更新预测。

用原厂 / md380 解码器打分的实验（PESQ，两份材料对原厂编码器的差之和）：

| 改动 | 结论 |
|---|---|
| 加权量化 | 有用（关掉 −0.14） |
| 清浊音迟滞 1.3 | 有用（关掉 −0.03） |
| 静音帧不更新预测 | 有用 |
| 按量化后清浊音取幅度 | 没用 |
| 浊音阈值 0.6 → 0.5 | 略好（+0.02） |
| 电平斜坡 −38～−20 → −45～−30 dB | 好（+0.04），但要注意停顿噪音（空中听感） |
| 编码电平 +1.4 dB（OUT_GAIN 2 → 1.7） | PESQ 不变，**响度与原厂一致**（RMS 1420 对 1454） |
| 基频跳变代价 3 | 中文大幅变差（2.53）：声调需要基频灵活 |
| 基频跳变代价 0.5 | 中文好（3.185），dam 差（3.436） |

基频是两难：中文声调要灵活，英文长元音要平稳。固定代价解决不了，要从基频估计本身入手（见第 6 节）。

当前（默认 + 浊音阈值 0.5 + 斜坡 −45～−30）编码器经原厂解码器：zh6 3.13（原厂 2.97），dam 3.50（原厂 3.53）。

## 5. 其他发现

- DVSI 的 b3/b4 比特位置与标准草案（mbelib、OP25）不同（已修，已提交）。
- DVSI 编码器 32 个 b1 码字都用；mbelib 的 V/UV 表用于解码是对的。
- 电台原厂编解码器 ≡ md380-emu（同一个 DVSI 版本）；跟 DVSI 测试向量的比特不同（版本不同），但参数很接近。
- PESQ 对“机器人颤音”不敏感：空中试听觉得不如原厂的版本，PESQ 反而更高。所以基频平稳度要单独看。

## 7. 夜间迭代（11-06 凌晨）

### 7.1 基频：倍频错误出在清浊音过渡的边缘

把我们和 md380 的逐帧基频并排打出来：**平稳浊音段里两者几乎一样**；大跳变几乎都在清浊音过渡处，而且多是倍频错误
（例如 114 Hz 附近突然 348 Hz = 3 倍，md380 给 83 Hz），这些帧的低频带还判成了浊音，合成出来就是字头字尾短促的
“机器人”声。用已知基频的合成信号测：我们的估计器在平稳信号上很准（帧间 86～97 % 不变，均方误差 0.5 级），所以
问题不在估计精度，而在**没有周期性的帧上硬给了一个基频并判了浊音**。

| 尝试 | 结果 |
|---|---|
| 量化迟滞（新基频离上一级不到 h 级就沿用） | 只把“跳 1 级”变成“不变”，大跳变不减；h = 1.6 明显变差 |
| 基频平滑（中值 / 1:2:1） | 统计可以做得和 md380 一模一样，但 PESQ 降 0.14～0.19：DVSI 的平稳不是事后平滑来的 |
| 更长的基频细化窗（320、400 点） | 更差 |
| 倍频检查只在周期性好时做；跟踪器约数检查计入跳变代价 | 倍频跳变略减，PESQ 基本不变 |
| **E(P) > 0.8 的帧沿用上一帧基频；E(P) > 0.85 的帧不判浊音** | **合计 +0.106 → +0.162**；倍频跳变 zh6 74 → 54，clean 67 → 45，dam 7 → 3 |

（中间有一次 zh6 掉到 1.6，是 bug：基频先对所有帧估完再逐帧分析谐波，用了最后一帧的 E(P)；已改为按帧保存。）

## 8. 定点 C 版进固件（11-06）

### 8.1 C 版

- `c/ref/`：双精度，逐行照 Python，和 Python 逐位一致（`c_eval.py` 对比）。
- `c/ambe/`：定点，给电台。CK803S 无 FPU（实测软浮点乘约 272 周期、加约 202；整数加 2、乘 4 周期左右，平均每条指令约 2 周期），
  所以只在每帧几次的控制量上用 float。编码第一版 24.5 ms，改成整数 FFT、整数拟合、整数 E(P) 等后约 11 ms（RAM 测试镜像，
  关中断）。电台上编码、解码与电脑上的 `ambe_cli` 逐位一致。
- 内存紧：编码器状态压到 7 KB（int16 输入历史、E(P) 只留三帧、拟合结构共用一份），编解码共用 8 KB 工作区。

### 8.2 进固件

- `src/dmr/vocoder.c`：`vocoderEncodeFrame` / `vocoderDecodeFrame`；`src/dmr/codec.c` 的 `codecEncodeBlock` / `codecDecode`
  调用它们（一帧 = 两块 80 点 wav 缓冲）。
- 代码和状态在 0x44400 的 RAM（`ckcpu.ld` 的 `.vocoder_overlay`），`vocoder_sync()` 在 HR_C7000 任务第一次编解码时拷入。
  （当初原厂 blob 和我们的两个段同一个 VMA、不同 LMA，轮流拷入；2026-11-07 起不再支持原厂编解码器。）
- 坑：`ambe_prof[]` 固件里只开了 8 项、编码器用到 12 号，多出的写坏了相邻的 `loaded`，每帧都重新载入、编码器每帧重置，
  发出去只有静音帧。改成 `AMBE_PROF_N` 统一声明。

### 8.3 空中问题和定位（都靠写频线读电台 RAM 里的临时记录）

| 现象 | 定位方法 | 原因 | 修正 |
|---|---|---|---|
| 发射“嗓子哑” | 记录发射时的比特和话筒采样，在电脑上重编码对比 | 话筒带约 2470 直流 + 开头冲击，基频被打到 P≈20，全判清音 | 编码器输入去直流（`dc_block`） |
| 刷机后第一次发射没声音 | 计数：话筒中断（向量 60）一次都没来 | 跳到引导程序重启不复位外设，AUDIO_CONTROL 第 4 位保持着 | `dmr_sound_init()` 清掉；后来改用看门狗整片复位 |
| 收热点信号断续、爆音 | 记录送去播放的采样和每块的时间 | `codecDecode` 在关中断的临界区里，15 ms 挡住每 10 ms 一次的播放中断 | 临界区里只拷数据，出临界区解码 |
| 发射高频不如原厂 | 同一段话筒录音分别用我们和原厂的编码器编码 | 3.5～4 kHz 判浊比例低（18 % 对 64 %） | 未改（见 algorithm.md 第 5 节） |
| 字词之间过渡不自然、开头爆音 | 录发射开头的原始话筒采样和事件时刻 | ① 每次发射才切 MIC_MUT，冲击到 −32000；② 采集开始 ADC 从 12000 落到直流用 150 ms，编码器在帧头期间就看到了，状态被污染（峰值抬高、后面判成小声） | MIC_MUT 按模式设（原厂做法）；`TX_START_4` 丢积压时 `codecInit()` 重置编码器；去直流从第一个样本起算 |

用户空中确认：接收不再断续；发射开头无爆音，字词之间和原厂差不多。

### 8.4 速度和 RAM

| 阶段 | 解码 / 帧 | 编码 / 帧 | RAM |
|---|---|---|---|
| 表在 Flash，代码在 RAM | 4.85 ms | 15.4 ms | 75.4 KB |
| 常用表放 RAM | 2.46 | 13.1 | 约 75 |
| 代码全在 Flash（表在 RAM） | 2.13 | 10.7 | 约 58 |
| 编码器代码回 RAM（Flash 总线串话筒） | 2.13 | 12.8 | 71.9 |
| 余弦 / 旋转因子四分之一周期、窗表减半、PRBA24 乘积现算 | 2.40 | 13.1 | **53.4** |

原厂：解码 3.66、编码约 13 ms，RAM 74.8 KB + 12.9 KB 缓冲区 + 30 KB SRAM。

结论：RAM 单端口，小循环在有缓存的 Flash 里更快；随机查的大表放 Flash 很慢；会影响话筒的代码（编码器）不放 Flash。
`-Os` 编码器省 2.6 KB 但 16 ms，不用。
