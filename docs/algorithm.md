# 我们的 AMBE+2 声码器：算法

DMR 半速率声码器（AMBE+2，3600 bit/s，其中 2450 bit/s 语音、1150 bit/s 纠错），20 ms 一帧，8 kHz 采样，每帧 160 个样本。
本文描述我们自己实现的编码器和解码器**最终定下来的做法**（2026-11-06）。研究过程和实验数据见 `notes.md`，代码说明见
`../README.md`。

三份实现，算法相同：

| 实现 | 位置 | 用途 |
|---|---|---|
| Python | `py/ambe_encoder.py`、`py/ambe_analysis.py`、`py/ambe_decoder.py` | 研究基准，参数都是模块常量，方便试验 |
| C 双精度 | `c/ref/` | 和 Python 逐位一致，用来检查定点版的误差 |
| C 定点 | `c/ambe/` | 嵌入式用（在 DM-32 的 CK803S 上跑）。没有 FPU：整数和查表实现，每帧只有几次 float |

文中“原厂”指 DM-32 原厂固件里的编解码器，它和 md380-emu（MD-380 固件里的 DVSI 声码器）逐位相同，所以评估都用 md380-emu
代替电台。

---

## 1. 帧格式（`ambe_frame.c` / `py/ambe_frame.py`）

一帧语音参数是 9 个量化索引 b0..b8，共 49 bit：

| 索引 | 位数 | 含义 |
|---|---|---|
| b0 | 7 | 基频（120 个值；120～123 擦除，124、125 静音，126、127 单音） |
| b1 | 5 | 清浊音码字（32 个，每个给出 8 个 500 Hz 频带的清浊音） |
| b2 | 5 | 增益差分 |
| b3 | 9 | PRBA24：频谱残差块均值的 DCT 第 2～4 项（512 个码字） |
| b4 | 7 | PRBA58：第 5～8 项（128 个码字） |
| b5..b8 | 5、4、4、3 | 四个频块的高阶 DCT 系数（HOC） |

49 bit 加纠错成 72 bit：前 12 bit 用 Golay(24,12)，接着 12 bit 用 Golay(23,12) 并按 C0 的值加伪随机掩码，其余 25 bit
不保护；再按固定表交织。DVSI 的 b3/b4 比特位置与标准草案（mbelib、OP25）不同，以 DVSI 测试向量为准。Golay 译码用
校验子查表（`AmbeGolayErr`，8 KB，留在 Flash）。

## 2. 解码器（`ambe_dec.c` / `py/ambe_decoder.py`）

从 mbelib（ISC 许可）出发，用 md380 黑盒探测逐项向 DVSI 调整。

### 2.1 帧类型

- **语音帧**：解量化出基频 w0、谐波数 L、每个谐波的清浊音 Vl 和幅度 Ml。
- **静音帧**（b0 = 124、125）：按 w0 = 2π/32、L = 14、全部清音合成，**幅度乘 0.25**（DVSI 播静音帧约衰减 11～13 dB）；
  **不更新预测状态**（TIA-102.BABA-1 的做法，DVSI 如此；mbelib 会更新）。编码器的解码器镜像也这样，否则静音后第一帧的
  增益和频谱预测与商用解码器对不上，字词之间过渡不自然。
- **纠错多的帧**（Golay 纠正 > 3 位）：重复上一帧参数，最多连续 3 次，之后静音。
- **擦除帧**（b0 = 120～123）：静音。
- **单音帧**（前 6 bit 全 1 且纠错 ≤ 3）：按单音 / 双音表合成（DTMF 等），连续相位；`ambe_tone.py`。

### 2.2 参数解量化（`ambe_parms.c`，即 mbelib 的 `decodeAmbe2450Parms`）

- b0 → w0、L（查表）；b1 → 每个 500 Hz 频带的清浊音，谐波 l 落在频带 int(16·l·f0)。
- 增益 γ = Δγ(b2) + 0.5·γ_prev。
- 频谱：PRBA24/58 码字给出 8 个块均值的 DCT（R），逆 DCT 得块均值；每块再加 HOC 的高阶系数，块内逆 DCT 得残差 T(l)。
  块的划分由 `AmbeLmprbl[L]` 给出。
- 对数幅度 log2 Ml = T(l) + 0.65·（上一帧 log2 M 按 l·L_prev/L 线性插值）− 0.65/L·Σ插值 + γ − 0.5·log2 L
  （预测系数 0.65）。
- 定点：码本 Q12，DCT 用查表余弦，log2 / exp2 查表，Ml 为 Q6（上限 0xFFFFFF）。

### 2.3 频谱增强（mbelib 的公式，全强度）

W_l⁴ = M_l²·0.96π·(1 + ρ² − 2ρ cos(w0 l)) / (w0·Rm0·(1 − ρ²))，ρ = Rm1/Rm0（Rm0、Rm1 为 M 的 0、1 阶自相关），
W 限制在 0.5～1.2；只对 8l > L 的谐波；最后整体乘一个系数保持总能量不变。探测得 md380 对每个谐波的增益
= 0.95 × 这个公式 + 0.66 dB，所以 **DVSI 用的就是它，全强度**。只增强浊音谐波试过，更差。定点版在 log2 域算。

### 2.4 浊音合成

- 总增益 2.35（输出电平与 md380 对齐，三类帧相差 0.2 dB 以内）。
- 每个谐波一个正弦；相位 PSI 按 (w0_prev + w0)·l·N/2 逐帧推进。
- **相位分散**：每个谐波加固定的伪随机相位偏移（`AmbePhaseDispQ32`），高于 L/4 的谐波再加与清音谐波数成比例的随机相位
  （go-ambe2 的发现，dam 3.185 → 3.240）。
- 前后两帧都浊、l < 8 且基频变化小于 10 % 的谐波：**幅度线性插值、相位二次插值**，一个正弦连续过渡（IMBE 式 134～138，
  mbelib 注释掉了）；其余：上一帧的正弦和这一帧的正弦用合成窗 Ws（321 点）交叉淡化。
- 定点：相位用 uint32（2³² = 2π），余弦查 1025 点的四分之一周期表（`cos_q12()` 折叠，值与整周期表相同），幅度 Q4。

### 2.5 清音合成（替代 mbelib 的正弦加随机相位）

mbelib 在 2700 Hz 以上的清音谐波上加 `rand()`，均值不为零，加窗后成了低频“噗噗”声。我们改成**频域整形的白噪声**：

1. 512 点频谱的每个频点填入高斯近似噪声（4 个均匀随机数之和）。
2. 只保留清音谐波 l 的频带 [(l − ½)w0, (l + ½)w0)，每个频带缩放到功率等于幅度 Ml 的正弦（清音增益 0.77，
   清音和浊音一样乘总增益 2.35）；其余频点清零。
3. 512 点逆 FFT，取 2N 个样本，用 √Ws 和上一帧的后一半重叠相加。

### 2.6 输出

- 4 阶 Butterworth 高通，120 Hz（两节 RBJ 二阶，Q 0.5412 和 1.3066；DVSI 低频压得很低）。
- 限幅到 ±32760。

### 2.7 和 md380 的差距

md380 编码、我们解码 vs md380 自己解码：PESQ 约低 0.17～0.25（zh6 2.80 对 2.97）。电平、频谱都已对齐，差别在时域细节
（噪声质感、帧间过渡），go-ambe2 也卡在同一处。这只影响“我们收听商用电台”；对方听我们靠编码器。

## 3. 编码器（`ambe_enc.c` / `py/ambe_encoder.py` + `py/ambe_analysis.py`）

自己按 TIA-102.BABA 的思路和 go-ambe2 的发现实现（OP25 是 GPL，只作理解参考，不用其代码）。编码器延迟 1 帧
（`AMBE_ENC_DELAY`）：基频跟踪要向前看。

### 3.1 输入去直流

`y = x − x₁ + (1 − 1/128)·y₁`，Q15 整数运算（约 10 Hz 一阶高通），x₁ 从第一个样本起算（开头的直流不产生台阶）。
三份实现结果逐位相同。原因：DM-32 的话筒采样带约 2470 的直流，再加上发射开始时的冲击，会把基频跟踪打到 P≈20，
整段判成清音（听起来“嗓子哑了”）。DVSI 也在输入端做高通。

### 3.2 语音活动检测（VAD）和静音帧

- 每帧能量 e（dB，256 点汉明窗、去均值后的功率）。
- 底噪 floor：向下立即跟随，向上每帧最多 0.05 dB。峰值 peak：向上立即跟随，向下每帧 0.05 dB。
- 判为语音：e > max(floor + 15 dB, peak − 45 dB, 20 dB)；语音后拖尾 1 帧。
- 非语音帧发**静音帧**：b0 = 124、b1 = 16，每个频带的功率作为舒适噪声照常量化。与原厂的静音判决逐帧一致约 88 %。
- 帧电平 level = e − peak，供清浊音判决用（3.6）。

### 3.3 频谱

每帧中心在输入的 160k − 200 处（与 DVSI 对齐）：256 点汉明窗、去均值，512 点实 FFT（拆成 256 点复数 FFT），去掉窗的
线性相位，得 257 个频点 S(k)。定点：输入归一到 13 bit，FFT 每级减半防溢出，旋转因子查 513 点的四分之一周期表
（`cos2048_q15()`），输出 S 为 12 bit 加指数 ex。另存 |S|² 的前缀和，频带能量 O(1) 求出。

### 3.4 基频：E(P) 跨帧跟踪（`compute_E`、`track`）

1. 301 点：1 kHz 低通（21 抽头对称 FIR）后乘基音窗 w_I²，算自相关 r(t)，t = 20..151（4 个滞后一起算）。
2. 周期网格 P = 20..128，步长 0.5（217 个点）。每个 P：
   E(P) = (1 − P·max(w_I²)·Σ_m r(mP) / r(0)) / (1 − P·Σw_I⁴)，r 在半样本处线性插值。E 越小越周期。
3. **无周期的帧 E = 1**：静音；或 1 kHz 以下能量不到全部的 3 %（擦音）；P > 100（长周期视为无周期）。
4. 跟踪：
   - 向后：在上一帧周期 ±20 % 内找 E0(P) + |ln P − ln P_prev| 最小（跳变代价系数 1），加上前两帧的 E。
   - 向前：E0(P) + min(E1 + 跳变) + min(E2 + 跳变)（看后面两帧），单调队列在 O(NP) 内求出 ±20 % 窗口的最小值。
   - 约数检查：向前最优 P 的 P/d（d = 2..）若代价够接近（≤ 0.85 且 ≤ 1.7 倍、≤ 0.4 且 ≤ 3.5 倍、≤ 0.05 且 ≤ 5 倍）就取约数。
   - 向后代价 ≤ 0.48，或不比向前（加跳变）差，就用向后的，否则用向前的。
   - 记下选中周期的 E（track_e），供后面判决。

### 3.5 基频细化（`refine`、`pitch`）

1. 在跟踪给出的周期 p 的 ±3 % 内取 13 个点，每点做**谐波拟合**（3.6）求 3 kHz 以下的拟合误差占能量的比例，取最小；
   再二分 4 轮（步长 0.25 % 起，每轮减半），最后在最优点和两侧做抛物线插值。每次 `refine` 约 23 次拟合。
2. 周期性好（误差 < 1.0）时，检查 1/3、1/2 倍周期：细化后误差不比原来大 0.05 以上就改用它（防倍频）。
3. 半频检查：2 倍周期 ≤ 100 时，看 2 倍周期下 400～2000 Hz 的奇次谐波能量：在偶次的 6 dB 以内，并且 2 倍周期更接近
   上一帧，就改用 2 倍周期（只在低于一半时检查，不会把真倍频当错）。
4. **E > 0.8 的帧沿用上一帧的基频**（过渡处没有周期性时不硬给一个新基频）。
5. 每帧平均约 52 次谐波拟合（每次约 23 个谐波），是编码器最大的开销（电台上约 2.9 ms）。

### 3.6 谐波拟合（`harmonic_fit`）

对每个谐波 l，在频带 [(l − ½)w0, (l + ½)w0) 内用窗的频域响应 W(f − l·w0) 对 S 做最小二乘：

- 投影 N = Σ W(k − l·w0)·S(k)，ww = Σ W²，拟合能量 proj = |N|²/ww（不超过频带能量 en）。
- W 是 256 点汉明窗的变换，按实数、偶对称、每个 512 点频点 64 个采样点制表（`AmbeWinTQ12`，2049 点）。
- 误差 = en − proj。

### 3.7 清浊音（`harmonics`）

- 在**量化后的** w0（b0 的表值）和它的 L 上重新拟合。
- 按 500 Hz 频带（码本的分辨率）：频带内各谐波的误差之和 < 门限 × 能量之和，判浊。
- 门限 = 0.8 × quiet × 迟滞：
  - quiet：电平斜坡，峰值以下 25 dB 内为 1，42 dB 以下为 0（低电平帧原厂也少判浊）；再乘 E 斜坡，track_e 0.4 以下为 1、
    0.8 以上为 0；track_e > 0.85（或周期 ≥ 95 时 > 0.3）直接为 0（无周期的帧不判浊）。
  - 迟滞：上一帧该频带浊则 ×2，清则 ÷2（防止来回翻转造成“机器人”声）。

### 3.8 幅度

- 浊音谐波：拟合正弦的幅度，|N|/√ww 换算成余弦幅度后除以 OUT_GAIN 1.7（编码电平与原厂一致）。
- 清音谐波：频带功率对应的正弦幅度 √(4·en / (NFFT·ΣW²)) / 1.7。
- 都取 log2，下限 log2(10⁻³)。定点版在 log2 域（Q12）直接算。

### 3.9 量化（`quantize`）

1. b0：表中对数距离最近的 w0。
2. b1：32 个码字中，按谐波能量加权的清浊音不一致最少的。
3. b2：γ = mean(log2 Ml) + ½·log2 L，量化 γ − ½·γ_prev。
4. 残差 r(l) = log2 Ml − 0.65 × 上一帧（量化后）对数幅度的插值预测，与解码器的公式一致（编码器带一份**解码器状态镜像**，
   每帧用自己的比特解码一遍更新预测，静音帧不更新）。
5. b5..b8：各频块残差的 DCT 高阶项，最近的 HOC 码字（作为初值）。
6. **b3、b4 联合加权搜索**：重建是线性的，残差 ≈ A24·v + A58·u + Σ Hᵢ·hᵢ（A、H 由块划分和 DCT 决定，每个 L 算一次）。
   加权 w_l = √(M_l / max M)（大幅度谐波更重要）。先不加权各取误差最小的 32 个 PRBA24、16 个 PRBA58 候选，再在 32 × 16 对里
   求加权误差最小的一对（二次型展开，交叉项一次算出）。
7. 给定 b3、b4，每个频块的 HOC 在其余项固定时按加权误差重选。
8. 打包成 49 bit，再加纠错交织成 72 bit。

### 3.10 评估结果

经 md380（= 电台原厂解码器）解码，对原始输入的 PESQ：

| 材料 | 原厂编码 | 我们编码 |
|---|---|---|
| zh6（THCHS-30 六人中文） | 2.967 | 3.16 |
| dam（DVSI 测试向量） | 3.534 | 3.44 |
| clean（DVSI 测试向量） | 3.255 | 3.26 |

THCHS-30 十个说话人分别测，全部比原厂好，平均 +0.25（v7）。PESQ 对“机器人颤音”不敏感，最终以空中试听为准：
空中试听与原厂差不多；高频（3.5～4 kHz）判浊比例低于原厂（约 18 % 对 64 %），高频略不如原厂。

## 4. 定点实现要点（`c/ambe/`）

- **数值格式**：log2 值、码本 Q12；E(P)、跟踪器 Q16；旋转因子、窗 Q15；合成 Q4 / Q8；相位 uint32（2³² = 2π）。
  log2 / exp2 用 257 点表加线性插值。CK803S 上 32 位乘法和除法是硬件指令，64 位乘除是库函数（慢），尽量避免。
- **工作区共用**：编码的 FFT、E(P)、跟踪、量化和解码的合成轮流用一块 8 KB 的 `ambe_scratch`。
- **表**：`py/gen_c_tables.py` 生成。常用的 23 张（约 17 KB）加 `AMBE_RAM_DATA`，固件放进 RAM；
  余弦和旋转因子只存四分之一周期，PRBA24 的两两乘积现算。
- **一致性**：电台上的输出和电脑上同一份 C 代码（`bin/ambe_cli.exe`）逐位一致；双精度参考版与 Python 逐位一致。
- **固件里的速度**（每帧，`vocoder_bench.py time`）：解码 2.40 ms、编码 13.1 ms（原厂 3.66、约 13）。
  编码的大头：基音 6～7 ms（谐波拟合约 2.9、E(P) 约 1.6、跟踪其余约 0.6）、量化约 2.4、频谱约 0.7。
- **RAM**：53.4 KB（编码器代码 12.5 KB、常用表、编解码状态和工作区），原厂 74.8 KB 加 12.9 KB 缓冲区和 30 KB SRAM 的表。

## 5. 可以继续做的

- 编码器提速：先用一次拟合粗判 1/2、1/3 倍周期，明显不好就不做整轮细化（每帧可少约 40 % 的拟合）。
- 高频清浊音：3.5～4 kHz 判浊太少，试过放宽高频段门限（数据上接近原厂），未上机定。
- 语音活动检测：预读 1 帧、拖尾 3 帧、峰值上升限速（防止咔哒声抬高峰值），Python 里试过，字头字尾更接近原厂，未采用。
- 解码器与 md380 的剩余差距（2.7）。
